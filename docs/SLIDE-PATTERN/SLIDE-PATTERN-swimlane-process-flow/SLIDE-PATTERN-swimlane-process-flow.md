# SLIDE-PATTERN-swimlane-process-flow

このファイルはスライドのコンテンツエリア（タイトル行より下の領域）のレイアウトパターン定義書です。SLIDE.mdと組み合わせてAIツールに渡すことで、このパターンのスライドを生成できます。タイトルエリア・ページ番号・装飾はSLIDE.mdの `Slide Frame` セクションで定義されるため、このファイルには含みません。

## Overview
**パターン名：** swimlane-process-flow
**概要：** 横方向のスイムレーン3本（部門・役割ごと）にプロセスボックスを左→右へ配置し、レーンをまたぐ矢印で部門間の受け渡しを表現するプロセス図。判断分岐はひし形で示し、差戻しは破線矢印で描く。「誰が・いつ・何をするか」を1枚で可視化する。
**適したシーン：** 部門横断プロセスの可視化、業務改革（BPR）の現状分析・将来像提示、引き継ぎ・ボトルネック箇所の議論、システム化範囲の合意形成

## Elements（各要素の役割）

| 要素 | 役割 | 推奨テキスト量 |
|------|------|--------------|
| レーンラベル（左端） | 担当部門・役割・システムを示す | 各2〜5文字、レーンは3本（最大4本） |
| プロセスボックス | 各ステップの作業内容 | 4〜7文字、全体で7〜9個 |
| ステップ番号バッジ | 実行順序を明示（レーンをまたいでも追える） | 数字1桁 |
| 判断分岐（ひし形） | Yes/No で流れが分かれる判断点 | 4〜6文字、1〜2個まで |
| 分岐ラベル（承認/否認等） | 矢印の条件を示す | 2〜6文字 |
| レーンまたぎ矢印 | 部門間の受け渡し（引き継ぎ点＝改善候補） | テキストなし |
| 凡例 | 線種・図形の意味を補足 | 1行 |

## Usage Guide（AIへの使い方）

### プロンプト例

```
SLIDE.md と SLIDE-PATTERN-swimlane-process-flow.md を参照して、
以下の業務フローをスイムレーン図のスライドにしてください。

【レーン（上から）】営業 / 審査 / システム

【プロセス（番号順）】
1. 申込受付（営業）
2. 書類確認（営業）
3. 一次審査（審査）※2から受け渡し
4. 与信判定（審査・判断分岐）
   - 承認 → 5へ ／ 否認 → 2へ差戻し（破線）
5. 契約手続き（営業)
6. 口座開設処理（システム）
7. 開設完了通知（システム）
8. 利用開始案内（営業・最終ステップは強調）

【スライドタイトル】
法人口座開設プロセスの部門間フロー（現状）
```

### 注意点
- レーンは3本が基本、最大4本まで（5本以上は文字が小さくなり判読不能になる）
- ボックスは全体で7〜9個に絞る（10個超なら2枚に分割するか粒度を上げる）
- ステップ番号バッジを必ず付ける（レーンをまたぐと順序を追いにくくなるため）
- レーンまたぎ矢印の本数＝引き継ぎ回数。改善提案では「またぎが多い＝非効率」の論点に使える
- 差戻し・例外フローは破線＋ラベルで1〜2本まで。主フローの視認性を優先する
- 最終ステップは背景を一段濃く（#EEEEEE）してゴールを示すとよい
