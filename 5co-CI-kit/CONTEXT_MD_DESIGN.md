# 案件フォルダの md 体系設計（正本）

> 制定: 2026-07-07。AI-Objective-MGMT の全案件フォルダに適用する「md の役割・命名・置き場所・読み順」の統一設計。
> 個々のルール本文は Drive ルート CLAUDE.md（CI正本ブロック）が正。本書はその**地図**。

## 全体像（1案件フォルダの標準形）

```
<案件フォルダ>/
├── CLAUDE.md                                  ← 【ルール層】案件の掟
├── 次回セッション起動コード_<名前>_<日時>.md      ← 【入口層】再開はここから（直下に最新1枚のみ）
├── （制作物・データ・作業サブフォルダ …）
└── _context/
    ├── active-context_<名前>.md                ← 【状態層】社員別の現在地
    ├── editing_<デッキ名>_<名前>.lock.md       ← 【ロック層】編集中の宣言（編集完了で削除）
    └── handoff/
        └── <YYYY-MM-DD_HHMM>_<名前>.md         ← 【履歴層】引き継ぎ蓄積（削除禁止）
```

## 4層の役割と読み書きタイミング

| 層 | ファイル | 答える問い | 読む | 書く | 枚数 |
|---|---|---|---|---|---|
| 入口 | `次回セッション起動コード_<名前>_<日時>.md` | **どう始めるか**（貼るだけの1コマンド＋落とし穴） | 再開時に人間が最初に | hand-off のたび新時刻で作り直し | 直下に最新1枚（旧は handoff/ へ移動） |
| ルール | `CLAUDE.md` | **何を守るか**（案件固有の規約・データ統治・置き場） | セッション開始時に自動 | 設置時＋規約が変わった時のみ | 1枚 |
| 状態 | `_context/active-context_<名前>.md` | **いまどこか**（進行中の状態・未完・次の一手） | セッション開始時（自分の分） | セッション終了時＋状態変化時 | 社員ごと1枚 |
| 履歴 | `_context/handoff/<日時>_<名前>.md` | **どう来たか**（意思決定と経緯のスナップショット） | 「handoff から再開」時・引き継ぎ時 | hand-off トリガ（成果物区切り/90分/リスク工程前）で追加 | 蓄積（削除・改変禁止＝人材資産） |
| ロック | `_context/editing_<デッキ名>_<名前>.lock.md` | **誰が編集中か**（衝突防止） | 成果物の編集開始前に必ず | 編集開始時に作成・完了時に削除 | 編集中のみ存在 |

## 編集ロック（同一成果物の衝突防止・複数人協業）

デッキHTML等の**成果物は案件フォルダに正本1枚**（Drive が全員へ最新版を自動配布）。
同時編集の衝突（Drive は HTML をマージできず後勝ち・複製化で事故る）をロック規約で防ぐ:

1. **編集開始前**: `_context/` に他人の `editing_<同じデッキ名>_*.lock.md` が**無いか必ず確認**。
   あれば編集せず「◯◯さんが編集中（開始時刻）」と作業者に伝え、読み取り専用で待つ
   （先に進める作業＝データ集計・文言案の下書き等に切り替える）
2. **無ければ**: `editing_<デッキ名>_<名前>.lock.md` を作成（内容: 開始時刻・編集箇所の予定・
   セッション識別メモ）→ 編集開始
3. **編集完了**: ロックを削除 → handoff に変更内容を記録（何を・なぜ変えたか）
4. **stale ロック**: 開始から**3時間超**のロックはクラッシュ残骸とみなし、作業者に確認のうえ
   削除して引き継いでよい（本人の最新 handoff を先に読む）

並行作業が本当に必要な大型デッキのみ、セクション別HTML分割→結合ビルドの発展形を管理者と相談。

## 命名規約

- 名前＝**姓のローマ字**（メールの姓部分。例: wakamatsu）。日本語名は起動コードmdのみ可（Finder視認性優先）
- 日時＝`YYYY-MM-DD_HHMM`（**時刻まで必須**・実時刻を取得して書く。同日複数回の hand-off に対応）
- 上記4種以外の md（依頼_・背景説明_・報告_ 等の一時文書）は役目が終わったら `_context/handoff/` へ移動（直下を散らかさない）

## ライフサイクル（1セッションの流れ）

1. **開始**: 起動コードmd を貼る（or フォルダで立ち上げ）→ CLAUDE.md・VERSION・自分の active-context・最新 handoff を読む
2. **作業中（二段構えの自動保存）**:
   - **起動コードmd＝15分スロットリング**：作業の区切りごとに実時刻を確認し、前回保存から
     **15分以上経過していたら**新時刻で更新（軽量5〜8文なので高頻度でも安い）。
     稼働がない間は更新しない＝状態が変わっていないので最後の版が正確なまま。
     クラッシュで失うのは最大でも実働15分ぶん
   - **handoff スナップショット＝大トリガのみ**：成果物完成の区切り／90分経過／リスク工程前
     （経緯と意思決定を含む重い文書なので頻度を抑える）
3. **終了**: active-context 更新 → 起動コードmd が最新であることを確認 → 完了報告

## 自動設置（社員の作業ゼロ）

- `_context/` と active-context は**無ければセッションが自動作成**
- 案件フォルダに CLAUDE.md が無ければ、そのフォルダで最初に立ち上がったセッションが
  `5co-CI-kit/CLIENT_CLAUDE_TEMPLATE.md` から生成・{{}}を実内容へ置換して設置してから作業を始める

## 退職・異動時（ピープルマネジメント）

その人の `handoff/` 一式＋`active-context_<名前>.md` が引き継ぎ書の実体。
後任は各案件の最新 handoff と起動コードmd から再開できる（口頭引き継ぎに依存しない）。
