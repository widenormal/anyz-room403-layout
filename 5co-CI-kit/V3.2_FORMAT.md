## 表紙CIコンセプト（全CIスライド規則・2026-07-09 制定）

**すべての CI スライドの表紙には、右下に CI コンセプト説明ブロック `.cover-ci` を必ず載せる。**
「水晶玉で市場を透視し、戦略を磨く。」のタグラインと、ロゴマーク（水晶玉＝市場を透視する5・
Strategy, refined.）の由来を短く添えることで、初見の相手にも 5co のブランド姿勢が一目で伝わる。

- **正典テキストは `ci_head.cover_ci_block()` が単一情報源**（`COVER_CI_TAGLINE` / `COVER_CI_BODY`）。
  由来はブランド正典 `LOGO_HANDOFF.md` §4。文言はブランド概念のみ＝顧客データ非依存（Tier0安全）。
- **CSS は正典 `.cover-ci` / `.cover-ci-h`**（`ci-format-v3.2.css`・右下配置／`--ink-85`／右寄せ）。
- **共有ビルダー `ci_v2_lib.cover()` は既定で自動付与**（`ci_concept_html` 省略時に
  `cover_ci_block()` を必ず挿入）。bespoke ビルダー（`build_html_monthly.py`／`build_w1_july.py` 等）も
  `import ci_head; ci_head.cover_ci_block()` で同じ正典を消費する（属人的な手書き文言＝ドリフト源は禁止）。
- **検査**：`slide_overflow_check.py` が `cover-full`（`pd-divider` 除く）に `.cover-ci` が無い表紙を
  `COVER_CI?` として表示（非ゲート・目視差し戻し用）。

## 生成・検査・出力の規定

1. **生成**：本キットのフォーマットに**文言・数値のみ**差し替え（CSS/色/フォント/レイアウト改変禁止）。数値はデータ由来のみ（手打ち・推測禁止）
   - **伝わりやすさ最優先**：文章の羅列スライドを作らない。主張・数値・比較は、内容に合う**フレームワーク図・グラフ・表**で構造化して示す（v3.2 の8型と 99種 SLIDE-PATTERN から選ぶ。型選びは `framework-recommend` スキルが支援）
   - **文言は「問いへの答え」方式（`COPY_GUIDE.md`＝crystal text・文言の正・必読）**：タイトル＝読者の問いへの答え／チャート1文目に「図の読み方:」／判断に「なぜ」の因果／専門用語は初出で日常語併記／誠実トーンの定型
1.5 **変換（PPT・旧資料→CI）の項目一致原則**：元資料のテーブル項目（列・行・指標名・単位）を
   **欠落・改名・統合・並べ替えしない**（デザイン＝CIが正／**データ項目＝元資料が正**）。
   - はみ出しゲートに掛かっても**列を削って解消しない**。解消手段は 1:表の分割（複数スライド化）
     2:密度高の型（`pdstr` 等）への変更 3:規定内のフォント/パディング調整 の順で検討
   - 変換後、**元資料の項目リストと突き合わせて差分ゼロを確認**してから配布（照合結果を報告に含める）
1.5b **表の分離の忠実再現（2026-07-09 制定）**：原本PPTで指標群（例: Object売上／通常期日販／広告経由）や
   ブロック（例: ブランド）が**隙間で分離**されている表は、CI変換後も**同じ位置に分離を再現**する
   （1枚の格子へ統合しない＝原本の情報設計の保全）。
   - 実装＝透明スペーサー方式（ヘッダ・列幅整合が保たれ、はみ出しゲートも1表で通る）。分離を使う表に
     `class="skg"` を付与し、列グループ間はヘッダ1行目 `<th class="gp" rowspan="2">`＋各行 `<td class="gp">`、
     行ブロック間は `<tr class="brsp"><td colspan="{実列数}"></td></tr>`（colspan はスペーサー列を含む実列数）。
   - CSS は `ci-format-v3.2.css` の `table.skg .gp / tr.brsp`（正典・改変禁止）。
1.6 **共通HEAD原則（案件ビルダーの正典消費・2026-07-07 制定）**：案件の自動ビルド
   （NatureLab `build_html_monthly.py`／WELLA 等）は、正典CSSを**コピー・inline再実装せず**、
   `ci_head.py` で連結する（`html = template.replace("<!--CI_HEAD-->", ci_head.style_block())` または
   `python3 5co-CI-kit/ci_head.py` の出力を HEAD に挿入）。
   - **なぜ**：CSSを手元コピーすると正典改定（Hoefler化・縦罫撤去等）が自動で届かず、
     連結方式を案件ごとに即興実装すると、その実装差自体が新たなドリフト源になる
     （2026-07-07 WELLA 世代遅れ事故の再発防止・連結方式は正典側で1つに固定）。
   - 連結対象は `VERSION` の format: 行が唯一の宣言（版上げ時は VERSION 更新だけで全案件が追従）。
   - 出力冒頭の版スタンプ `/* 5co-CI ci_head vX.Y — … */` が「ci_head 経由で組まれた」証跡
     （parity 検査・監査の機械判定マーカー）。
2. **検査**：`slide_overflow_check.py`（あふれ）と `check_text_overlap.py`（要素同士の重なり＝absolute配置の死角）を必ず通す（両方 OK になるまで配布不可。`ci-finalize.sh` が自動でゲートする）。通過後、**タイトルだけを縦に読んで主張が通るか**、**全スライドのコメント（所見・洞察・チャート注記）が誠実トーンか**を最終チェック（`COPY_GUIDE.md` 原則1・5）
3. **出力**：`ci-finalize.sh`（PDF＝フォント埋込／PPTX＝1枚1画像・編集不可／Slides＝Drive 変換）

### 版上げ5点チェックリスト（PRマージ前）

1. **トークン整合**: `python3 scripts/check-slide-ci-parity.py` が OK（廃止トークン `--navy`/`--powder`・旧hex・Georgia混入なし）
2. **はみ出し**: `python3 5co-CI-kit/slide_overflow_check.py <対象html>` が OK
3. **コメント文面の整合**: CSS/HTML内の「トークン互換シム」等の解説コメントが**現行の正規トークン名（`--ink`/`--crystal`）で記述**されているか目視確認
   （逆転コメントは検査ツールでは検出困難＝文字列としては合法。レビュー時の目視必須）
4. **ドキュメント同期**: `CHANGELOG.md`・`V3.2_FORMAT.md`・`SLIDE_DESIGN_GUIDELINES.md` の記述が変更点と一致
5. **全案件への影響確認**: `5co-CI-kit` 配下の変更は git 派生リポ（App認証sync）＋ Drive 案件コピー
   （`drive-canonical-refresh.sh`）の両経路で伝播する。破壊的変更（トークン値・レイアウト寸法）は
   事前に影響案件を洗い出す
