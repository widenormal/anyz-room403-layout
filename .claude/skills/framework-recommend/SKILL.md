# framework-recommend（フレームワーク・レコメンダ）

CIスライドを作るとき、**作り手が知っている型だけに寄らないよう**、内容に合う図と「未経験かもしれない
フレームワーク図」を提案する。狙いは **全社員が 99 種のフレームワークに自然に触れられる**こと。

## いつ発火するか

- **CI制作フローの標準ステップ**：`ci-weekly-deck` / `5co-ci-slide` / 「CIスライド作って」で本文スライドを
  設計する各タイミングで、そのスライドの「言いたいこと」を入力に呼ぶ。
- **オンデマンド**：「どんな図がいい？」「この戦略に合うフレームワークは？」「フレームワーク提案して」。

## 手順

1. 対象スライドの **意図（戦略・主張・データの性質）を1文に要約**する（例：「現状と目標のギャップを2軸で整理」）。
2. レコメンダを実行（決定論アシスト・外部LLM不要）：
   ```bash
   python3 scripts/framework_recommend.py "<スライドの意図/戦略/内容>" --n 3
   ```
   出力は **● 最適（内容に合う図）** と **○ 発見枠（未経験かものフレームワーク図）**。
3. 各候補に **「この戦略に効く理由」を一言**添えて提示する（テンプレ任せにせず、なぜその型が主張を強めるか）。
   - 例：`risk-matrix-2x2` →「影響度×発生確率の2軸で、優先して潰すリスクが一目で伝わる」
4. **発見枠は必ず1つ見せ、軽く後押しする**（「普段使わない型ですが、この内容なら整理が効きます」）。
   ただし押し付けず、**最終選択はユーザー**。選ばれた型で制作に進む。
5. 選んだパターンは **CI v2 で描く**。99種は `scripts/ci_pattern_adapter.py` で CI v2（A4・3色・φ）へ
   オンデマンド変換できる（全99種が3色QA合格済み）：
   ```bash
   python3 scripts/ci_pattern_adapter.py docs/SLIDE-PATTERN/SLIDE-PATTERN-<name>/SLIDE-PATTERN-<name>.html -o <out>.html
   ```
   生成HTMLの**本文ダミーを実値に差し替え**、`5co-CI-kit/slide_overflow_check.py` で検査して仕上げる。
   寸法・配色の正は `docs/SLIDE-PATTERN-CI-ADAPTER-SPEC.md`。

## 出力フォーマット（ユーザー提示）

```
このスライドの意図: 〇〇
● おすすめ（内容に合う）
  1. <pattern>  — この戦略に効く理由: …
  2. <pattern>  — …
○ 発見（普段使わないかも）
  ・<framework図>  — この内容ならこう効く: …
どれで描きますか？（迷ったら 1）
```

## 原則

- **発見枠で"未経験の型"に触れさせる**のがこのスキルの主目的。毎回1つは知らないかもしれない型を見せる。
- 押し付けない・比較表で丸投げしない（CLAUDE.md の提案スタイル：主導1案＋代替、確認ループは原則1回）。
- 機密データは扱わない（型の選択のみ）。レコメンドは INDEX のメタデータだけで動く。

## 知識ベース

- `docs/SLIDE-PATTERN/SLIDE-PATTERN-INDEX.md` … 99種 ×（概要・適したシーン・カテゴリ）。
- `scripts/framework_recommend.py` … バイグラム重なりで採点＋framework系カテゴリ/名称に発見加点。
- `docs/SLIDE-PATTERN-CI-ADAPTER-SPEC.md` … 選んだ型を CI v2（A4・3色・φ）で描くための寸法仕様。
